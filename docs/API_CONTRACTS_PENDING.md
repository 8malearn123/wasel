# عقود API المنتظرة من Backend

هذا الملف يخص الواجهة فقط، ولا يغيّر الخادم. لكل وظيفة يذكر:
- العقد الذي تنتظره الواجهة؛
- الترحيل الذي ينشئها في `supabase/migrations`؛
- ما تفعله الواجهة اليوم وهي غائبة.

**القاعدة العامة في الواجهة:**
- الوظيفة الغائبة لا تمنح أي صلاحية افتراضية.
- البيانات التجريبية لا تُعرض على أنها حقيقية.
- الشاشة تقول بوضوح إن الخدمة غير مفعّلة على الخادم.

**ما يحدث عند تطبيق الترحيل:** تنتقل الواجهة إلى الخدمة الحقيقية تلقائيًا، دون تعديل في الكود. الاستثناء هو الخدمات التجريبية في الجدول الأخير، فهي تحتاج تبديلًا في `src/services/index.ts`.

## الدوال (RPC)

### `my_permissions()`
| البند | القيمة |
|---|---|
| الترحيل | `20261004100200_rbac.sql`، ثم `20261020100100_custom_roles.sql` |
| المدخلات | لا شيء. المستخدم يُعرف من الجلسة |
| المخرجات | `text[]`: مفاتيح صلاحيات المستخدم في متجره، مثل `products.view` و`pos.access` |
| الاستدعاء من | `src/hooks/usePermissions.ts`، عبر `callOptionalRpc` |
| السلوك اليوم (404 `PGRST202`) | تُطبَّق خريطة صلاحيات الدور المطابقة لدالة الخادم `legacy_role_permissions` (ملف `src/lib/legacyRolePermissions.ts`). يُسأل الخادم مرة واحدة في الجلسة. أي خطأ آخر (شبكة أو 500) يعني «لا صلاحيات» مع رسالة فشل، ولا تُمنح صلاحية افتراضية |

### `get_subscription_state()`
| البند | القيمة |
|---|---|
| الترحيل | `20261004090000_secure_subscriptions.sql` |
| المخرجات | `jsonb`: `{ found, status, effective_status, plan, plan_id, ends_at, days_remaining, is_locked, server_time }` |
| الاستدعاء من | `src/hooks/useSubscription.ts` |
| السلوك اليوم (404) | تُحسب حالة الاشتراك من جدول `subscriptions` نفسه، بالمنطق ذاته (انتهاء التجربة أو الاشتراك يعني «منتهٍ»). الفرق الوحيد أن الوقت يؤخذ من ساعة الجهاز لا من الخادم |

### `wholesale_parties()`
| البند | القيمة |
|---|---|
| الترحيل | `20261023100100_wholesale_parties.sql` |
| المخرجات | `TABLE (merchant_id uuid, name text, phone text)`: الطرف الآخر في صفقات الجملة التي يشارك فيها المتجر فقط |
| الاستدعاء من | `src/hooks/useWholesale.ts` |
| السلوك اليوم (404) | يظهر «—» مكان اسم الطرف الآخر، ولا يُخترع اسم. يُكتب تحذير واحد في الـ console |

### `wholesale_listing_items()`
| البند | القيمة |
|---|---|
| الترحيل | نفسه |
| المخرجات | `TABLE (listing_id uuid, item_type text, name text, brand text, model text, sku text)` |
| السلوك اليوم (404) | يُعرض وصف المنتج المحفوظ مع العرض إن وُجد، وإلا «—» |

## الجداول

### `roles` و `permissions` و `role_permissions` و `user_roles`
| البند | القيمة |
|---|---|
| الترحيل | `20261004100200_rbac.sql`، ثم `20261020100100_custom_roles.sql`، ومعه الدوال `save_custom_role` و`delete_custom_role` و`assign_member_role` |
| الاستدعاء من | `src/hooks/useCustomRoles.ts` و`src/hooks/useAuth.tsx` |
| السلوك اليوم (404 `PGRST205`) | الأدوار المخصصة تُحفظ كلقطة في `activity_logs` (`entity_type = 'custom_roles'`). العضو صاحب الدور المخصص يبقى على الخادم «كاشير»، أقل دور. **حدود هذا الحل:** الخادم لا يعرف هذه الأدوار، فلا يفرضها. ما يمنعه الدور المخصص يُمنع في الشاشات فقط |

### `employees`
| البند | القيمة |
|---|---|
| الترحيل | `20261004100300_employees.sql` |
| الأعمدة | `id, merchant_id, branch_id, merchant_user_id, employee_number, full_name, email, phone, job_title, department, hire_date, status(active/inactive/archived), notes` |
| السلوك اليوم | بيانات الموارد البشرية الإضافية تُحفظ على هذا الجهاز فقط، مع تنبيه ظاهر بذلك في القسم. قائمة الموظفين نفسها مبنية على مستخدمي المتجر (`merchant_users`) |

### `product_media`
| البند | القيمة |
|---|---|
| الترحيل | `20261004100100_product_media.sql` |
| الأعمدة | `id, merchant_id, item_type(device/accessory/repair_part), item_id, media_type(image/model_3d), storage_path, public_url, thumb_url, alt_text, sort_order, is_primary, width, height, bytes, mime` |
| الاستدعاء من | `src/hooks/useProductMedia.ts` |
| السلوك اليوم (404) | **تغيّر في هذه الجولة.** معرض الصور يقول «معرض صور المنتجات غير مفعّل على الخادم بعد» بدل «لا توجد صور». يتوقف الرفع قبل أن يصل أي ملف إلى التخزين. أي خطأ قراءة آخر يظهر كـ«تعذّر تحميل صور المنتج» مع زر إعادة المحاولة |

## على الخادم وحده (لا يمكن للواجهة ضمانه)

| المطلوب | لماذا |
|---|---|
| سياسات RLS تتحقق من استحقاق الباقة | قفل الأقسام في الواجهة يمنع العرض فقط. الجداول ما زالت قابلة للقراءة عبر الـ API لأي مشترك |
| فرض حد الفروع | تفعيل فرع فوق الحد غير ممنوع على الخادم. الترحيل جاهز في PR #122 |
| فرض الأدوار المخصصة | يأتي مع جداول الأدوار أعلاه |

## خدمات تجريبية في الواجهة (`src/services/index.ts`)

كل شاشة تعتمد على خدمة تجريبية تعرض شريط «بيانات تجريبية». لربط أي منها بالخدمة الحقيقية:
1. اكتب تنفيذًا للواجهة البرمجية في `src/services/contracts`.
2. ضعه مكان الخدمة التجريبية في `src/services/index.ts`.
3. احذف اسمها من `MOCKED`، فيختفي الشريط من شاشتها وحدها.

| الخدمة | الشاشة | الحالة |
|---|---|---|
| attendance | الفريق ← الحضور | تجريبية، مع الشريط |
| devices | الفريق ← أجهزة البصمة | تجريبية، مع الشريط |
| policy | الإعدادات ← سياسة العمل | تجريبية، مع الشريط |
| ai | الذكاء الاصطناعي | غير مفعّلة. الشاشة تقول ذلك ولا تعرض أي تحليل مختلق |
| shipping | لا تستخدمها أي شاشة | صفحة الشحن تعمل على طلبات المتجر الحقيقية |
