# wasel-staging — مشروع الاختبار

مشروع Supabase منفصل نجرّب عليه الترحيلات والدوال والصلاحيات وسيناريوهات المتجر **قبل** الإنتاج. يبنيه ويختبره سير العمل `.github/workflows/staging.yml`.

## ما فيه

| المحتوى | المصدر |
|---|---|
| الهيكل | نسخة من هيكل الإنتاج كما هو، مع سجل الترحيلات المطبّقة |
| البيانات | **المتاجر التجريبية الثلاثة فقط**. صفوف المتاجر الأخرى لا تُنسخ، ولا ما يربط متجرًا تجريبيًا بمتجر حقيقي (مثل طلب جملة بينهما) |
| البيانات الشخصية | تُستبدل **داخل استعلام القراءة من الإنتاج** بقيم اختبار قبل أن تخرج منه. لا تصل القيم الحقيقية إلى staging |
| الجداول المستبعدة | التحويلات البنكية (`merchant_payouts`) ومديرو المنصة (`platform_admins`) |
| الحسابات | حسابات دخول خاصة بـstaging لكل عضو في المتاجر الثلاثة، بكلمة مرور واحدة من السر `STAGING_TEST_PASSWORD` |

**البيانات الشخصية المستبدلة:** أسماء العملاء وجوالاتهم وبريدهم وعناوينهم، وأرقام IMEI (برقم اختبار يبدأ بـ00)، وIBAN والحساب البنكي والسجل التجاري، وأكواد الدخول، والملاحظات الحرة، وعنوان IP.

## إنشاء المشروع (مرة واحدة، من صاحب الحساب)

1. Supabase → **New project** باسم `wasel-staging`:
   - في نفس منطقة الإنتاج.
   - بنفس نسخة Postgres إن أمكن (سير العمل يحذّر إن اختلفت).
   - الباقة المجانية تكفي.
2. **كلمة مرور قاعدة البيانات:** يولّدها Supabase. احفظها في مدير كلمات المرور ولا ترسلها في أي محادثة.
3. أضف في GitHub → Settings → Secrets and variables → Actions:

| السر | من أين |
|---|---|
| `STAGING_DB_URL` | staging → Connect → Session pooler (المنفذ 5432)، مع كلمة المرور |
| `STAGING_API_URL` | `https://<staging-ref>.supabase.co` |
| `STAGING_ANON_KEY` | staging → Project Settings → API → anon key |
| `STAGING_SERVICE_ROLE_KEY` | staging → API → service_role key. **مفتاح staging فقط؛ لا تضع مفتاح الإنتاج أبدًا.** سير العمل يرفض المفتاح إن كان لمشروع الإنتاج |
| `STAGING_TEST_PASSWORD` | كلمة مرور جديدة طويلة (16 حرفًا فأكثر) لحسابات الاختبار في staging فقط |

يحتاج أيضًا `SUPABASE_DB_URL_RO` (دور القراءة في الإنتاج، `readonly_role.sql`).

## التشغيل

Actions → **Staging (wasel-staging)**:

| الوضع | ما يفعله |
|---|---|
| `init` | يبنيه، ثم يشغّل السيناريوهات كخط أساس |
| `rehearse` | يطبّق الترحيلات المعلّقة على staging بالترتيب المختار، ثم يشغّل السيناريوهات |
| `test` | السيناريوهات فقط |
| `reset` | يفرغ staging ويعيد بناءه. يعمل فقط على قاعدة عليها علامة `wasel-staging` |

**ترتيبات `rehearse`:**
- `hold-12` (الافتراضي): كل الترحيلات عدا ترحيل الاشتراكات 20261023100000.
- `only-12`: هو وحده، مع جدول قبل/بعد.
- `with-119`: الكل ثم ترحيل PR #119.

## الإلغاء

- احذف أسرار `STAGING_*` من GitHub.
- احذف المشروع من Supabase → Project Settings → Delete project.
